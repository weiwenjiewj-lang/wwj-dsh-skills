# 元数据规范（受控词表）

> 本规范是技能的数据契约。知识库中每个 md 文件都带一段 YAML frontmatter，字段取值必须来自下列**封闭词表**，
> 否则合规闸门与知识自诊断器无法可靠判定。
>
> 当前知识库状态：**271 个文件全部已带 frontmatter**（Zone A/B 为 15 字段；Zone C 另加 14 个专属字段）。

---

## 一、字段清单（15 个，顺序固定）

| # | 字段 | 含义 | 取值 |
|---|---|---|---|
| 1 | `title` | 文档正式名称 | 自由文本，不带库内前缀（`参考_`/`ex02_`/`_完整版` 等） |
| 2 | `doc_type` | 文档类型（中文细分） | §二 词表 |
| 3 | `doc_type_class` | 文档类型（英文粗分，供工具使用） | `law` / `regulation` / `normative_doc` / `national_standard` / `industry_standard` / `monograph` / `paper` / `other` |
| 4 | `doc_number` | 文号 / 标准号 / ISBN / 文章编号 | 见 §四；无则 `待确认` |
| 5 | `issuing_body` | 发布机关 / 主编单位 / 期刊 / 出版社 | 自由文本，须文件内可查证 |
| 6 | `publish_date` | 发布日期 | `YYYY-MM-DD`，精度不足可用 `YYYY-MM` 或 `YYYY`；无则 `待确认` |
| 7 | `effective_date` | 施行/实施日期 | 同上；参考层文献填 `不适用` |
| 8 | `status` | 效力状态 | §三 词表 |
| 9 | `superseded_by` | 被何文件替代/废止 | 标准号或文件名，多个用半角逗号分隔；无则 `无` |
| 10 | `supersedes` | 替代/废止了何文件 | 同上 |
| 11 | `zone` | 知识分层 | 仅 `A` 或 `B` |
| 12 | `scope` | 适用范围 | `national` / `provincial` / `local` / `不适用` |
| 13 | `chapter_relevance` | 关联的模板内容节点 | YAML 列表，元素取自 §五 |
| 14 | `source_url` | 可验证来源链接 | **仅当文件正文含 DOI/URL 时填写**；否则 `待确认` |
| 15 | `compliance_relevance` | 合规相关性强度 | `直接红线` / `间接红线` / `约束性` / `方法依据` / `背景参考` |

## 二、`doc_type` 词表

**Zone A：** `法律`、`法律修改决定`、`行政法规`、`部门规章`、`规范性文件`、`规范性文件（流域管理机构）`、`国家标准`、`行业标准`、`地方性法规`、`地方规范性文件`、`地方规范性文件（政策解读）`、`规划文件`、`规划文件（市级）`、`编制模板`、`编制模板（附件）`、`技术指南`、`技术文件（编制提纲）`

**Zone B：** `专著`、`技术手册`、`期刊论文`、`学位论文`、`团体标准（编制说明）`、`规划报告（县级，含具体行政区资料）`、`库索引（元数据基础设施）`

> **判定原则：以文档的法律效力层级定，不以它在库里的存放目录定。**
> 因此 `03-专家资料\03-技术标准\` 下的 GB/T、TD/T、MT/T 虽放在"专家资料"目录，仍判为 Zone A。

**`doc_type` → `doc_type_class` 映射**（工具用）：

| doc_type | doc_type_class |
|---|---|
| 法律、法律修改决定 | `law` |
| 行政法规、部门规章、地方性法规 | `regulation` |
| 规范性文件、规范性文件（流域管理机构）、规划文件、编制模板、编制模板（附件）、技术指南、技术文件（编制提纲）、地方规范性文件、地方规范性文件（政策解读）、规划文件（市级） | `normative_doc` |
| 国家标准 | `national_standard` |
| 行业标准 | `industry_standard` |
| 专著、技术手册 | `monograph` |
| 期刊论文、学位论文 | `paper` |
| 团体标准（编制说明）、规划报告（县级…）、库索引 | `other` |

## 三、`status` 词表

**Zone A：** `现行有效`、`试行有效`、`已废止`、`已失效`、`已被代替`、`试行期满（…）`、`待核验（…）`、`编制阶段（…）`、`未生效`、`待确认`
- 有修正案的用括号补充：`现行有效（2021年5月28日修正）`
- **判定规则**：以 `现行有效` / `试行有效` 开头视为现行；`已废止`/`已失效`/`已被代替`/`试行期满`/`未生效` 触发告警并在无替代依据时阻断；`待核验`/`编制阶段` 一律不得进入硬约束

**Zone B：** `已出版`、`已发表`、`参考性`、`编制阶段（…）`

## 四、`doc_number` 书写规则

- 发文字号：照录，中括号用〔〕，如 `办水保〔2023〕177号`、`国函〔2015〕160号`
- 法规：主席令号 / 部令号，如 `水利部令第53号`
- 标准：标准号，如 `GB 50433-2018`、`SL/T 277-2024`
- 图书：`ISBN 978-7-81107-959-3`
- 期刊论文：文章编号，如 `文章编号1000-0941(2023)01-0008-05`
- **无编号或正文未载 → `待确认`。不得用文件名、目录名反推编号。**

## 五、`chapter_relevance` 词表

取值来自《生产建设项目水土保持方案编制模板》（办水保函〔2026〕232号）附件1 的**内容节点**：

```
全域
1  1.1.1  1.1.2  1.2  1.3  1.4  1.5  1.6.1  1.6.2  1.7  1.8  1.9
2  2.1  2.2.1…2.2.8  2.3  2.4  2.5  2.6  2.7  2.7.1…2.7.7
3  3.1  3.2  3.3  3.4  3.5  3.6  3.7
4  4.1.1  4.1.2  4.2.1  4.2.2  4.3.1  4.3.2  4.4.1  4.4.2  4.4.3
5  5.1  5.2
6  6.1  6.2  6.3  6.4
7  7.1  7.2  7.3.1  7.3.2  7.4  7.5  7.6  7.7  7.8
8  8.1  8.2.1  8.2.2  8.3  8.4
9  9.1.1  9.1.2  9.2
10
表1  附表  附件  附图
```

**两条关键规则**：

1. **只贴内容节点**。模板中的 `1`、`1.1`、`1.6`、`2`、`2.2`、`2.7`（仅标题无要求文字者除外）等**容器节点不承接标签**。
   例：`1.1` 是容器 → 不贴；`1.1.1` 是内容节点 → 贴。
2. **`全域` 只用于真正对全篇普遍适用的文件**（水土保持法、水利部令第53号、2026版模板、GB 50433-2018、中办国办意见、生态环境法典、办水保〔2023〕177号 等 9 个）。
   `全域` 依据在自诊断器中**只计入"继承"列，不计入阈值**——否则每一节都"有依据"，真缺口被掩盖。

## 六、`compliance_relevance` 词表与硬规则

| 值 | 含义 | 典型对象 |
|---|---|---|
| `直接红线` | 含强制性条文或直接设定方案编制义务/审批条件，违反即不予许可 | 水土保持法、水利部令第53号、GB 50433-2018、2026版模板、办水保〔2023〕177号 |
| `间接红线` | 相关法律/规划，划定禁止限制区域或程序义务 | 防洪法、黄河保护法、矿产资源法、生态环境法典、全国水土保持规划 |
| `约束性` | 推荐性标准或规范性文件，须执行但通常不构成许可否决点 | GB/T 系列、办水保〔2024〕57号、地方收费文件 |
| `方法依据` | **Zone B**：提供可引用的测算方法、设计原理、论证逻辑 | 水土保持设计手册、土壤侵蚀预报模型 |
| `背景参考` | **Zone B**：案例、现状、经验、趋势，仅作表达与佐证 | 矿区案例、综述、现状分析 |
| `表达参考` | **Zone C**：仅提供写作风格、章节展开、表格设计、论证逻辑 | 已批准的水土保持方案（应用范例） |

**硬规则（脚本强制校验，规则见 `rules.json` 的 `zone_consistency_rules`）**：
- Zone A 不得取 `方法依据` / `背景参考` / `表达参考`
- Zone B 不得取 `直接红线` / `间接红线` / `约束性` / `表达参考`
- **Zone C 不得取 `直接红线` / `间接红线` / `约束性` / `方法依据` / `背景参考`——只能取 `表达参考`**

## 六之二、Zone C（应用范例层）专属字段

`zone: C` 的文件在通用 15 字段之外**追加**下列字段：

| 字段 | 含义 | 取值 |
|---|---|---|
| `project_type` | 项目类型 | `市政与房建` / `矿山工程` / `输变电工程` / `铁路工程` / `油气与管道` / `火电与能源` / `水利枢纽与水电` / `公路工程` / `其他` |
| `project_name` | 范例的项目名称（**标识用，禁止进入产出**） | 自由文本 |
| `approval_level` | 审批层级 | `水利部` / `省级` |
| `approval_year` | 审批年份 | `YYYY` |
| `approval_period` | 审批期次 | `YYYY-MM` |
| `approval_basis_list` | 该方案**自身列明**的编制依据清单 | 逐字摘录的列表，初始 `[]` |
| `standard_system_at_approval` | 上述清单的**摘要标签** | `待确认` 或简述 |
| `superseded_basis` | 清单中**已确认被替代/废止**的项及替代件 | 与 `source_watchlist.json` 交叉检查后填，初始 `[]` |
| `source_chapter_system` | 该范例自身采用的章节体系 | 如 `老八章（GB 50433-2018 附录B）` |
| `chapter_mapping` | 映射到 2026 版 10 章的状态 | `pending`（默认，**不得挂载**）/ `verified`（人工核对语义后才可） |
| `topic_tags` | **主题挂载标签**（Zone C 唯一合法挂载维度） | 如 `防治责任范围`、`弃渣场`、`表土剥离与利用`、`投资估算`；初始 `[]` |
| `usable_for` | 文件级**默认**可用范围 | `["章节展开","语言风格","表格设计","论证逻辑"]` |
| `not_usable_for` | 不可用范围 | `["合规判断","参数取值","具体措施直接套用"]` |
| `local_file` | 库内落盘位置说明（**方案原件 PDF 已按库规约删除，库内只存 md**） | 固定为「本文件（方案原件 PDF 未保留，按库规约只存 md）」 |

> **`standard_system_at_approval` 不是"过时判定器"**：标准号变了不等于结论过时（要看相关条款内容是否变）；
> 标准号没变但条款修订了，结论反而可能失效。**该范例是否过时，不由本字段判定，而由 Zone A 现行状态（`source_watchlist.json`）裁决**，
> 且判定结果**只影响"是否可提示先例"，永不影响合规结论**。
>
> **`chapter_mapping` 是安全闸**：Zone C 几乎都是老八章结构，与 2026 版 10 章**同号不同义**
> （老 `1.5`＝防治目标，新 `1.5`＝水土流失预测结果）。因此**未标 `verified` 的范例一律不得按章节号挂载**，检索只能走 `topic_tags`。

## 七、写进技能的铁律

1. **Zone B 不得覆盖 Zone A。** 冲突时以 Zone A 为准，并**丢弃** Zone B 的冲突内容（不是标注保留）。
2. `compliance_relevance` 为 `方法依据` / `背景参考` 的文件，在写作指令中**必须带限定语**：
   > 「仅用于写作表达、论证逻辑与案例参考，不得引入与 Zone A 冲突的方法论或参数」
3. `status` 非现行有效的 Zone A 文件，**合规闸门必须阻断或降级提示**，并给出 `superseded_by`。
4. `status` 为 `待核验` 的文件**不得作为合规依据**，只能作为资料线索。
5. `doc_number` / `publish_date` / `effective_date` 为 `待确认` 的 Zone A 文件，**补全前不得作为正式方案的引用来源**，且闸门会置 `provisional=true`。
6. `source_url` 为 `待确认` 的文件**不得编造链接**。
7. **Zone C 不得作为任何合规结论的依据。** 不得写入 `hard_constraints`，不得参与 `blocked` 判定，不得引入其具体项目数据，**不得因其"曾经通过"而推定其做法在当前标准下仍然合规**。与 Zone A 冲突时一律以 Zone A 为准，**冲突的范例段落直接丢弃**，并标注「该范例依据的是旧标准，已忽略其合规内容」。
8. **Zone A 未明确规定时**，必须输出「**Zone A 未明确规定，以下为参考写法，需人工判断**」，**不得**直接采用 Zone C 的做法。
9. **Zone C 不得作为"章节完整性"判据。** 老八章范例缺第 4 章（表土）、第 5 章（弃渣场）是**范例的结构缺陷**，不是可以略过的依据。章节完整性只以 `template-tree.json` 为准。
